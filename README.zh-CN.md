# 数字员工岗位系统

这是一个面向真实组织协作的、文件优先的数字员工运行框架。它不追求“让更多 Agent 互相聊天”，而是让每项工作都具备明确主责、事实来源、验收证据和人工批准闸门。

## 解决什么问题

- 每项任务只有一个主责岗位，避免多 Agent 重复生产；
- AI 草稿、内部预验收、正式成果和对外动作严格分开；
- 交付必须链接证据和复验方式，不能只靠岗位自报“已完成”；
- 发布、提交、部署、采购、付款或资金转账、签署和删除必须经过人工批准；
- 任务卡和交付单保存在文件中，不依赖单次对话上下文。

## 八个参考岗位

| 编号 | 岗位 | 对结果负责 |
|---|---|---|
| C0 | 总控 | 识别对象、派工、冲突处理和内部验收 |
| C1 | 商务 | 商机、商务条款、合同及回款推进 |
| C2 | 媒体 | 品牌、内容生产和发布准备 |
| C3 | 方案 | 需求澄清、方案设计和演示原型 |
| C4 | 申报 | 政策申报、材料编制和证据一致性 |
| C5 | 交付 | 实施、里程碑、验收和风险 |
| C6 | 研发 | 正式源码、测试、安全、发布和运维 |
| C7 | 财务 | 财务记录、预算与成本审核、发票凭证和收付款对账 |

## 三道批准闸门

- **G0 启动批准：**新对象或重大工作线启动。
- **G1 内容批准：**某一版本成为正式内部基线。
- **G2 外部动作批准：**发送、发布、上传、提交、部署、采购、签署或删除。

内部检查通过、文件生成成功、API写入成功或页面提示成功，都不能自动等同于G1或G2。
